# Codexion — Agent Instructions

This is a 42 School C concurrency project. Follow these rules precisely when working in this codebase.

## Project Overview

**Codexion** is a Dining Philosophers variant. Coders (threads) sit in a circle sharing USB dongles. Each coder cycles through compile → debug → refactor. Compiling requires holding two adjacent dongles simultaneously. The simulation ends on burnout or when all coders reach a compile count target.

## Language & Standards

- **Language**: C only (C99/C11 compatible)
- **Compiler flags**: `-Wall -Wextra -Werror -pthread`
- **No global variables** — all shared state is passed through structs
- **No libft** — only the explicitly allowed functions may be used
## Norm compliance**: 42 Norm v4.1 (norminette) — full rules enforced; see "Norm Style Rules" section below

## Allowed Functions Only

```
pthread_create, pthread_join, pthread_mutex_init, pthread_mutex_lock,
pthread_mutex_unlock, pthread_mutex_destroy, pthread_cond_init,
pthread_cond_wait, pthread_cond_timedwait, pthread_cond_broadcast,
pthread_cond_destroy, gettimeofday, usleep, write, malloc, free,
printf, fprintf, strcmp, strlen, atoi, memset
```

Do **not** suggest or use any other library functions, including `<string.h>` functions beyond `strcmp`/`strlen`/`memset`, or `<stdlib.h>` beyond `malloc`/`free`/`atoi`.

## Architecture

- **One thread per coder** (`pthread_create`)
- **One monitor thread** — detects burnout, stops simulation
- **N dongles** arranged in a circle (coder `i` uses dongle `i` and dongle `(i+1) % N`)
- **Special case**: 1 coder → 1 dongle, only needs to grab it once to compile (or per the subject spec)
- Each dongle has: `pthread_mutex_t`, `pthread_cond_t`, a min-heap wait queue, release timestamp, in-use flag

## Scheduling

Two modes controlled by the `scheduler` argument:

- `fifo`: min-heap key = request arrival timestamp (monotonically increasing)
- `edf`: min-heap key = `last_compile_start + time_to_burnout` (earliest deadline wins); tie-break by coder ID

The heap must be a **custom binary min-heap** — no standard library priority queues.

## Dongle Cooldown

After a dongle is released, it is unavailable for `dongle_cooldown` ms. Use `pthread_cond_timedwait` with a calculated `struct timespec` deadline when the next waiter must sleep through the cooldown.

## Burnout Detection

The monitor thread polls all coder structs checking `current_time - last_compile_start`. Poll interval must be ≤ 1 ms to guarantee the 10 ms log deadline. When burnout is detected:
1. Lock `sim_mutex`, set `sim->over = 1`, broadcast on `sim_cond`
2. Print the burnout log under `log_mutex`
3. All threads check `sim->over` at each phase boundary and exit cleanly

## Logging Format

All output must be serialized through a `log_mutex`. Format exactly:

```
timestamp_in_ms X has taken a dongle
timestamp_in_ms X is compiling
timestamp_in_ms X is debugging
timestamp_in_ms X is refactoring
timestamp_in_ms X burned out
```

`timestamp_in_ms` = milliseconds since simulation start (use `gettimeofday` delta).

## Memory

- All `malloc`-allocated memory must be `free`'d before exit
- All mutexes and condition variables must be destroyed before exit
- All threads must be `pthread_join`'d before exit
- Detect and handle `malloc` failures — exit cleanly, no leaks

## Makefile Rules

Must include: `$(NAME)`, `all`, `clean`, `fclean`, `re`
Binary name: `codexion`
No unnecessary relinking (use `.o` dependency tracking).

## Norm Workflow Guardrails

- After editing any `.h` file or changing declaration alignment, always run `make norm` before concluding the task
- For struct members, typedef tails, and prototypes, align with real tab characters only — never use spaces for visual alignment
- If `norminette` reports `MISALIGNED_VAR_DECL`, `SPACE_REPLACE_TAB`, or `MIXED_SPACE_TAB`, inspect the exact whitespace with `cat -te` or equivalent before editing again
- Do not rely on editor or formatter alignment for 42 headers and C declarations; verify tab placement manually when touching headers

## Norm Style Rules (42 Norm v4.1)

All generated C code **must** pass `norminette` with zero errors. Rules marked `(*)` are not checked by norminette but are enforced during peer evaluation — violations cause project failure.

### Naming
- Structure names must start with `s_`; typedef names with `t_`; union names with `u_`; enum names with `e_`; global names with `g_`
- All identifiers (variables, functions, types) must be `snake_case` — lowercase, digits, and `_` only; no capital letters
- File and directory names must be `snake_case`
- Non-ASCII characters are forbidden except inside string/char literals
- `(*)` All identifiers must be explicit English words separated by underscores — no `f1`, `tmp2`, `a`, `b`, etc.
- Global variables not marked `const` or `static` are a norm error (unless the project explicitly permits them)

### Formatting
- Maximum **25 lines** per function body (not counting the opening/closing braces of the function itself)
- Maximum **80 columns** per line (a tab counts as the number of spaces it represents, not 1)
- Functions must be separated by exactly one empty line; no two consecutive empty lines anywhere
- Indent with **real tab characters** (ASCII 0x09, 4-char-wide) — not spaces
- Blocks inside braces must be indented; braces are **alone on their own line** except for `struct`/`enum`/`union` declarations
- Empty lines must contain no spaces or tabs; lines must not end with whitespace
- All variable names in the same scope must be aligned on the same column
- Pointer `*` must be stuck to the variable name, not the type: `char *str`, not `char* str`
- One variable declaration per line — no `int a, b;`
- Declarations and initialisations on the same line are forbidden, except for `static` and `const` variables
- In a function: one blank line between declarations and the first instruction; no other blank lines inside the function
- Only one instruction or control structure per line — no assignments inside conditions, no two assignments on one line
- When splitting a long line, indent the continuation; operators go at the **start** of the new line, not end of the previous
- Commas and semicolons (unless end of line) must be followed by a space
- Every operator and operand must be separated by exactly one space
- Every C keyword must be followed by a space, except type keywords (`int`, `char`, `float`, …) and `sizeof`
- Control structures (`if`, `while`, …) must use braces unless the body is a single instruction on a single line

### Functions
- Maximum **4 named parameters** per function
- Functions that take no arguments must be prototyped with `void`: `int foo(void)`
- All parameters in prototypes must be named
- Maximum **5 variables** declared per function
- `return` values must be in parentheses: `return (val);` — bare `return ;` for void functions
- There must be a single tab between the return type and the function name

### Typedef / Struct / Enum / Union
- Add a space between the keyword and the name when declaring: `struct s_foo`, `enum e_bar`
- All structure names in the same scope must be indented to the same column
- Structures must not be declared in `.c` files — declare them in headers only

### Headers (`.h` files)
- Allowed contents: `#include`, declarations, `#define`, prototypes, macros — nothing else
- All `#include` directives must be at the top of the file
- Never include a `.c` file in a `.h` or another `.c` file
- Every header must have an include guard: `#ifndef FILENAME_H` / `# define FILENAME_H` / `#endif`
- `(*)` Unused `#include`s are forbidden

### The 42 Header
- Every `.c` and `.h` file must begin with the standard 42 header comment block (login, email, creation date, last update)

### Macros and Preprocessor
- `#define` constants must be used only for literal/constant values — not to bypass the norm or obfuscate logic
- Multiline macros are forbidden
- Macro names must be ALL_UPPERCASE
- Preprocessor directives inside `#if`/`#ifdef`/`#ifndef` blocks must be indented
- Preprocessor instructions are forbidden outside global scope

### Forbidden Constructs
- `for` loops — use `while` instead
- `do...while` loops
- `switch` / `case`
- `goto`
- Ternary operator `? :`
- VLAs (Variable Length Arrays)
- Implicit types in variable declarations

### Comments
- Comments are forbidden **inside** function bodies; they must appear at the end of a line or on their own line (outside functions)
- `(*)` Comments must be in English and must be useful
- `(*)` A comment cannot justify a carryall/bad function (no functions named `f1`, `helper2`, etc. just to split lines)

### Files
- Cannot include a `.c` file in another `.c` file
- Maximum **5 function definitions** per `.c` file

### Makefile
- Mandatory rules: `$(NAME)`, `all`, `clean`, `fclean`, `re`; `all` must be the default rule
- No unnecessary relinking
- All source files must be **explicitly named** — no wildcards like `*.c` or `*.o`

## What NOT to Do

- Do not use global variables under any circumstances
- Do not use `sem_t` (semaphores) — not in the allowed list
- Do not use `pthread_detach` — all threads must be joinable
- Do not busy-wait (spin loops) — use condition variables for waiting
- Do not use `sleep()` — use `usleep()` only
- Do not add features not in the subject
- Do not refactor working code without being asked

## Common Pitfalls

- **TOCTOU on dongle state**: always check and claim inside the same mutex lock
- **Heap not under mutex**: the priority queue is shared; never read/modify it outside `dongle->mutex`
- **Monitor vs coder race on `sim->over`**: always read `sim->over` under `sim_mutex`
- **`pthread_cond_timedwait` spurious wakeups**: always re-check the condition in a `while` loop
- **Timestamp overflow**: use `long long` for millisecond timestamps to avoid 32-bit overflow
- **Single-coder edge case**: with 1 coder and 1 dongle, compile requires only that one dongle
